# Community

This community helps Product Managers, Product Marketers, and Business Analysts improve the **method** of market intelligence. It is not a place to publish competitive findings.

## The Rule at the Door

**Describe the method, not your findings.**

Do not post:

- a client or customer name
- a real competitor teardown or live-deal detail
- employer-confidential information
- material learned under a non-disclosure or other obligation
- personal information about a customer, learner, participant, employee, or research subject
- paid training material, client deliverables, or work created during a client engagement
- third-party material you do not have permission to submit

Use synthetic examples, fictional organizations, and `example.invalid` URLs. If you would be uncomfortable explaining the source and collection method on stage at the named company's user conference, do not post it.

Issues, comments, Discussions, pull requests, Project items, and attachments are all public surfaces. Deleting something later does not pull it back from notifications, copies, or event history.

## Choose the Right Door

| You want to... | Start with... |
|---|---|
| Ask a question, compare judgment, or share an experiment | The Open Question or Gap issue form |
| Report what the method caught or missed without sharing findings | The Field Report issue form |
| Name a specific gap that could become a change | The Open Question or Gap issue form |
| Propose a new skill | The Skill Proposal issue form |
| Submit an agreed change | A pull request |
| Report a credential, client name, or privacy problem | Follow [`SECURITY.md`](SECURITY.md), never a public post |

GitHub Discussions and a GitHub Project board are intentionally not enabled at this time. Issues hold concrete questions and proposed improvements; pull requests hold reviewed changes. The long-term criteria for opening a bounded thematic Project are recorded in [`ROADMAP.md`](ROADMAP.md).

## Valuable Contributions That Do Not Require Git

The easiest useful contributions are usually small:

1. **Sharpen a weak example.** Explain why a competent practitioner might ship it and what judgment error sits underneath.
2. **Improve a list or taxonomy.** Add the missing trap question, switching trigger, source category, or violation signal.
3. **Share a method-level field report.** Tell us which part of a sweep or framework helped or failed without sharing the company or findings.
4. **Identify a reference gap.** Point to a public, rights-clear source or regional practice the Project is missing.
5. **Propose a new skill.** Start here only when the contribution test clearly passes.

You can make a small file change entirely in GitHub's web interface: open the file, choose the pencil icon, make the edit, and select **Propose changes**. GitHub creates the branch and pull request for review.
